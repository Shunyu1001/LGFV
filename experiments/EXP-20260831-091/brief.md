## Falsifiable bottleneck

The tracked manuscript correctly describes the 94 Codex source-packet labels
as working reference labels pending independent human confirmation. Several
builders still encode or print them as `human_gold_standard`, `gold_outcome`,
`gold_standard_exit_type`, or equivalent human-gold language. A clean rebuild
therefore recreates claims that the project has explicitly rejected and can
also overwrite corrected table notes.

## Hypothesis and success criteria

A single canonical label-role registry can make the generated empirical
artifacts preserve the actual provenance without changing any observation,
exit type, score, inclusion flag, count, adjusted quantity, coefficient, or
sample composition. Success requires all of the following:

1. generated label-source and analytic-role values identify Codex
   source-packet working references separately from Codex LLM surrogates;
2. no generated paper table describes a working reference as human gold,
   human validated, author reviewed, or independently confirmed;
3. every visible table states that working references await independent human
   confirmation wherever that distinction bears on interpretation;
4. all row IDs, outcome labels, scores, inclusion flags, counts, rates,
   adjusted quantities, and model inputs are value-identical to the base
   build after a semantic-field normalization map;
5. the affected build commands are deterministic and a second execution
   leaves the worktree clean;
6. the paper compiles from `paper/` with the same 78-page count; and
7. immutable, ledger, label, master-pool, quantity, and package validators
   pass.

Any numerical, label, inclusion, or sample-composition change invalidates the
experiment. The experiment does not convert the working references into
independent human labels and does not alter the separate probability-frame
design.
